# ยกยอดเงินเดือนย้อนหลังจากระบบเดิม

ชุดสคริปต์ที่ใช้ทำเงินเดือน 8 งวดย้อนหลัง (26/12/2025 – 25/08/2569) ให้ตรงกับ
ไฟล์ `รายงานผลการคำนวณเงินเดือนสุทธิ` ของระบบเดิมทุกบาท — ทำเสร็จ 2569-09-08

ผลลัพธ์: สลิป 929 ใบ ตรงกับไฟล์ 928 ใบ (ที่เหลือคือ 690045 งวด มิ.ย. 704 บาท
ที่วันเริ่มงานในระบบขัดกับไฟล์)

## ลำดับการทำ

```bash
cd backend

# 0) เวลาเข้าออกงานต้องนำเข้าและล็อกให้ครบก่อน (ดู scripts/import-timesheet-file.js)

# 1) อ่านไฟล์เงินเดือนของระบบเดิมทั้งโฟลเดอร์ เก็บเป็น json ให้สคริปต์อื่นใช้
node scripts/legacy-payroll-import/parse-legacy-payroll-files.js

# 2) สร้างงวด + payroll run ทั้ง 8 งวด
node scripts/legacy-payroll-import/create-legacy-payroll-periods.js

# 3) เตรียมข้อมูลตั้งต้นให้ตรงกับที่ระบบเดิมใช้จริง
node scripts/legacy-payroll-import/build-legacy-compensation-history.js --apply
node scripts/legacy-payroll-import/shift-recurring-items-forward.js --apply
node scripts/legacy-payroll-import/shift-deduction-plans-forward.js --apply
node scripts/legacy-payroll-import/fix-overtime-work-type.js --apply

# 4) นำเข้ารายการเฉพาะงวด (เบี้ยเลี้ยง ค่าตำแหน่ง กยศ. ค่าปรับ ภาษี ฯลฯ)
node scripts/legacy-payroll-import/import-legacy-payroll-adjustments.js --apply
node scripts/legacy-payroll-import/exclude-adjustments-from-sso-base.js --apply

# 5) คำนวณเวลาใหม่ (ยอดหักลา/ขาดงานคิดเป็นเงินไว้ในสรุปเวลา ต้องใช้ค่าจ้างที่ถูก)
node scripts/legacy-payroll-import/unlock-attendance-summaries.js 2025-12-26 2026-08-25 --apply
node scripts/legacy-payroll-import/recalc-and-lock-attendance.js

# 6) คำนวณเงินเดือน แล้วเทียบกับไฟล์
node scripts/legacy-payroll-import/calculate-legacy-payroll-runs.js
node scripts/legacy-payroll-import/check-payroll-vs-legacy-file.js --out=<โฟลเดอร์รายงาน>

# 7) ปิดส่วนต่างที่เหลือ (กติกาของระบบเดิมที่คำนวณย้อนกลับไม่ได้) แล้วคำนวณอีกรอบ
node scripts/legacy-payroll-import/close-payroll-residual.js --apply
node scripts/legacy-payroll-import/calculate-legacy-payroll-runs.js
```

ทุกตัวรันซ้ำได้ และมีโหมดพรีวิว (ไม่ใส่ `--apply`)

## กับดักที่เจอระหว่างทาง

1. **ระบบเก็บค่าจ้างแถวเดียว** (อัตราปัจจุบัน) คนที่ขึ้นเงินเดือนระหว่าง 8 งวด
   จะได้อัตราใหม่ทุกงวด ต้องสร้างประวัติเป็นช่วง ๆ จากช่อง "อัตราค่าจ้าง" ในไฟล์
2. **ช่อง "วันทำงาน" คือจำนวนวันที่จ่ายจริง** ไม่ใช่ "มาทำงาน" — ใช้แยกรายวัน/รายเดือน
   (`เงินเดือน = อัตรา x วันทำงาน` คือรายวัน · `วันทำงาน = 30` คือรายเดือน)
3. **ประกันสังคมของระบบเดิมคิดจากเงินเดือนอย่างเดียว** ไม่รวมค่าตำแหน่ง/โอที
   และมี 58 คนที่ไม่ถูกหักเลย ต้องตั้ง `socialSecurityEnabled` เป็นช่วงตามไฟล์
4. **ภาษีต้องปิดการคำนวณอัตโนมัติ** (`taxEnabled = false` ในช่วงย้อนหลัง)
   แล้วใช้ยอดจากช่อง "ภาษี"/"หัก ณ ที่จ่าย" ในไฟล์แทน ไม่งั้นหักสองต่อ
5. **รายการประจำและแผนหักรายงวด (กยศ./กรอ./ค่าตำแหน่ง/ค่าเช่าห้อง) หักซ้ำ**
   กับรายการที่ยกมาจากไฟล์ ต้องเลื่อนวันมีผลไปเริ่มงวดถัดจากงวดสุดท้ายที่ยกยอด (ตอนนี้คือ 26/08/2569)
6. **ประเภทโอทีต้องดูจากช่องในไฟล์ (x1.0 / x1.5)** ไม่ใช่ดูว่าวันนั้นเป็นวันหยุด
7. **ยอดหักลาไม่รับค่าจ้าง/ขาดงาน คิดเป็นเงินไว้ในสรุปเวลารายวัน** ไม่ใช่ตอนทำเงินเดือน
   แก้ค่าจ้างย้อนหลังแล้วต้องปลดล็อก คำนวณเวลาใหม่ แล้วล็อกกลับ
8. **จำกัดคนในรอบด้วย `employeeIds` ตามรายชื่อในไฟล์** ระบบเดิมไม่ได้จ่ายทุกคนที่
   ยังมีสถานะพนักงานอยู่ (งวด ม.ค. ระบบมีเกินมา 3 คน)
9. **รายการเสริมที่นำเข้าไว้รอบก่อนโดยไม่ผูก `periodId`** จะลบไม่เจอตอนนำเข้าใหม่
   (ระบบจับคู่ด้วยวันที่มีผลได้เอง) แล้วถูกหยิบมาใช้ซ้ำสองชุด — งวด ส.ค. เคยเกินไป
   51,195 บาท ตรวจด้วยการนับรายการต่องวด แล้วลบชุดเก่าตามวันที่สร้าง
10. **`close-payroll-residual.js` ต้องหักผลของรายการปรับเดิมออกก่อนเทียบ** ไม่งั้น
    งวดที่ปิดส่วนต่างไปแล้วจะอ่านได้ว่าต่าง 0 พอสคริปต์ลบของเดิมทิ้งก็หลุดทั้งงวด
    (แก้ในสคริปต์แล้ว รันซ้ำได้ปลอดภัย)
11. **สรุปเวลาของคนที่พ้นสภาพก่อนวันเริ่มงวด จะค้างอยู่และขวางการล็อก** ตัวคำนวณ
    เก็บกวาดให้เฉพาะคนที่อยู่ในรายชื่อของรอบ — ลบแถวว่างพวกนั้นทิ้งก่อน
12. **งวดที่ยังไม่จบ ล็อกไม่ได้** ("ข้อมูลยังไม่ครบงวด 31 วัน") เป็นพฤติกรรมปกติ
    งวดปัจจุบันจึงค้างที่สถานะ REVIEWED จนกว่าจะถึงวันสิ้นงวด
